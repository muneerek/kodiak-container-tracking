# Kodiak — Vue customer presentation prototype

A responsive Vue 3 prototype for Kodiak's manually maintained container operations. No backend, API, real authentication service, or external tracking integration is used. Fonts and icons are bundled locally.

## Run locally

Requires Node.js 20.19+ and npm.

```powershell
npm install
npm run dev
```

Open the localhost address printed by Vite (normally http://127.0.0.1:5173).

```powershell
npm run build
npm run preview
npm test
```

`dist/` is the production static build. Serve it with a static web server; don't open index.html directly with a file:// URL. This prototype has not been published to the internet. A localhost link is only accessible on the machine running it.

## Demo access

Use the three one-click role cards on the login screen, or sign in with:

| Role | Email | Password |
|---|---|---|
| Admin | admin@kodiak.demo | Demo123! |
| Distributor | distributor@kodiak.demo | Demo123! |
| Supplier | supplier@kodiak.demo | Demo123! |

Supplier: Atlas Exports. Distributor: GulfBridge Distribution, linked to Atlas Exports, Coastal Foods, and the pending Evergreen Ceramics account. Kodiak admin sees all organizations.

Changes are saved to localStorage under `kodiak-demo-v1`. Session login uses sessionStorage. All roles in the same browser use the same demo records; other browsers/devices have separate copies. The sidebar's **Reset sample data** action restores the original eight sample journeys and all demo accounts, after confirmation.

This is a presentation prototype: all data is client-side, and passwords are stored as demo JSON. Do not enter real credentials or confidential business information. A production version requires server-enforced permissions and real authentication.

## Screens and behavior

- Login, supplier self-registration and pending account state.
- Admin, distributor, and supplier dashboards derived from their visible container records.
- Supplier and distributor directories/registration, user creation with working demo login.
- Supplier approval with distributor assignment.
- Container registration with route/date/cargo validation and inherited distributor assignment.
- Container search, status/supplier filters, tracking cards, full journey detail and timeline.
- Kodiak tracking updates, container allocation, holds/releases, and container restrictions.
- Supplier blacklist/release; blocked suppliers retain existing tracking but cannot submit new bookings.
- Country, state/region, and port directories with dependent location forms.
- In-app notifications generated by booking, tracking, and account actions, with read/unread state.
- Three reports: container register, route performance, and supplier activity, each with CSV export.
- Responsive desktop/mobile navigation, keyboard-accessible forms, inline validation, persisted sample data, and reset.

## Suggested 7-minute customer walkthrough

1. **Login:** show the three role cards and supplier registration button.
2. **Supplier:** enter through the Supplier demo card. Show the three Atlas containers. Register a new container with cargo, weight, package count, route, and future dates. Leaving its physical number blank demonstrates pending allocation.
3. **Admin:** sign out using the avatar at the top right, then enter Admin. Open the new registration, choose Update tracking, assign a physical number, select At origin, and add location and an operational note. Save and show the timeline.
4. **Distributor:** switch to Distributor. Show the new Atlas record and updated status alongside Coastal Foods; Pacific Components and Northstar shipments are not visible in this role.
5. **Admin management:** show supplier approval, distributor/user creation, location hierarchy, blacklist restrictions, and hold/release controls.
6. **Reports:** switch between the three reports and export a CSV. Filters apply to the container-register export.
7. **Mobile:** narrow the browser to show the compact dashboard, navigation drawer, and tracking detail. Tables scroll horizontally on small screens.

Use Reset sample data before the actual presentation to remove rehearsal changes.

## Prototype boundaries

- One registration represents one container journey; multi-container booking groups from the business plan are future scope.
- Booked means a recorded request, not carrier-confirmed space. Tracking advances only when Kodiak manually updates it.
- Countries/ports are manually maintained. The dashboard map is an illustrative network, not live GPS.
- Supplier registration is approved by Kodiak. Distributor and user registration are admin-managed.
- Chronological event entries are supported. Backdated corrections, document upload, invoicing, email/SMS/push, and production account recovery are not included in this presentation scope.
- Journey-level distributor assignment is retained. The prototype does not expose a supplier-transfer screen.
- Dashboard counters, report results, and notifications update from the local data. Seed records are dated September–October 2026; overdue counts use the browser's current date.

## Verification

The automated domain checks cover role scoping, pending/blacklisted booking eligibility, normalized duplicate container numbers, restrictions on future allocation, arrival-overdue rules, and retained distributor scope.

The source is in `src/App.vue`, styling in `src/style.css`, and seed data/domain helpers in `src/data.js`.
